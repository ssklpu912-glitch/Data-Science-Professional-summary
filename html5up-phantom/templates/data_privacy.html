Data & privacy

Where your data lives, how it's backed up, and what leaves this app.

Data retention & backup policy

Everything you enter — experiments, characterizations, research papers, protocols, projects, and tasks — is stored locally in this app's own SQLite database, plus any files you upload (images, data files, PDFs) under its static/uploads folder. Nothing is automatically deleted: entries stay until you explicitly delete them.

The server this app runs on backs up the database daily (via backup_db.py, using SQLite's own consistent-snapshot backup API rather than a plain file copy, so a backup can never catch a half-written state). The last 14 daily backups are kept. That protects against database corruption or a bad deploy — it isn't a substitute for your own copy, so if you want a portable snapshot in hand, use Export / download all my data at any time.

Privacy note

By default, your experimental data stays in this local database — it is not sent anywhere else. The exceptions are the features that inherently need to reach an external service:

  • Search Papers sends your search text (and filters) to Semantic Scholar, CrossRef, and arXiv to find literature. It does not send any of your logged experimental data.
  • Analyze / Summarize may fetch a paper's open-access PDF from its publisher/host to extract key points; it does not upload your own files or entries anywhere.

Because this tool can hold unpublished, pre-publication research, treat access to the machine/account running it the same way you'd treat any other lab notebook. Each account only sees and can act on its own experiments, papers, protocols, projects, and files — but treat your login itself with the same care, since anyone signed in as you has access to everything you've logged.
